# AI-Note

Turn a YouTube lecture into structured Notion notes with real frames from the video. Click **Take Notes** under a YouTube video. A pool of Go workers fetches the captions, writes notes with an LLM, captures the frames the notes refer to with ffmpeg, and publishes a Notion page.

It is a distributed system: a Chrome extension, an API gateway, RabbitMQ, a worker pool, Postgres and Redis, all started with Docker Compose. It survives killed workers, provider rate limits and failed frames. The full specification is [`docs/SRS.md`](docs/SRS.md).

## 1. Prerequisites

- **Docker** with Compose v2 (Docker Desktop on Windows/macOS).
- **Google Chrome**.
- A **Notion** account.
- A **Gemini API key**: free from [Google AI Studio](https://aistudio.google.com/apikey). Groq or OpenRouter also work (see [Configuration](#5-configuration)).
- Git Bash or WSL on Windows for the `scripts/*.sh` helpers (`scripts/setup.ps1` is a native PowerShell alternative for setup).

## 2. Base URL

The gateway listens on **`http://localhost:8080`**. The extension uses this by default, so a standard setup changes nothing in the extension.

## 3. Quick start

Clone to first Notion page should take under 15 minutes.

1. **Configure.** This creates `.env`, generates `TOKEN_ENC_KEY` and `ADMIN_TOKEN`, and asks for your Gemini key. Running it again never overwrites values you've set.
   ```bash
   git clone https://github.com/Oct8Hacker/ai-note.git && cd ai-note
   scripts/setup.sh            # Windows PowerShell: powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
   ```
2. **Start the stack.** It uses the prebuilt release images when they exist and otherwise builds from source (a few minutes the first time).
   ```bash
   docker compose -f deploy/docker-compose.yml --env-file .env up -d
   curl http://localhost:8080/healthz      # wait for "status": "ok" and "workers_alive": 2
   scripts/doctor.sh                        # checks the LLM key, yt-dlp, ffmpeg and YouTube access
   ```
3. **Load the extension.** Either:
   - download `ainote-extension-<version>.zip` from the latest [release](https://github.com/Oct8Hacker/ai-note/releases) and unzip it, or
   - build it yourself: `npm --prefix extension ci && npm --prefix extension run build` (output in `extension/dist/`).

   Then open `chrome://extensions`, turn on **Developer mode**, click **Load unpacked**, and pick the unzipped folder or `extension/dist`. The extension ID is always `lbmicegifohcileflpbjdanghkgigcia` (pinned by the manifest key; `scripts/extension-id.sh` prints it).
4. **Connect Notion** with Quick mode ([§6](#6-connecting-notion), 2 minutes): create an internal connection (Notion's Developer connections), give it access to a page called **AI Video Notes**, and paste the token into the popup's **Integration token** field.
5. **Take notes.** Open a YouTube video of at most 20 minutes with captions, click **Take Notes** under the player, and follow the progress in the popup. When it finishes, click **View in Notion**.

## 4. Default Notion destination

When a job doesn't name a destination (`notion_parent_id` omitted), the worker picks one in this order:

1. `NOTION_DEFAULT_PARENT_ID` from `.env`, if set (a page or database ID).
2. Otherwise, the page titled exactly **"AI Video Notes"** that is shared with the integration. If there are several, the oldest wins. Generated notes pages are never titled this way, so the default never drifts onto an earlier result.
3. Otherwise the job fails with `NOTION_NO_DESTINATION` ("Share a page called 'AI Video Notes' with the app").

The extension always sends an explicit destination: the one chosen in the popup's picker, which defaults to "AI Video Notes".

To switch provider, set `LLM_PROVIDER`, its key and `LLM_MODEL`, then restart the workers (`docker compose -f deploy/docker-compose.yml --env-file .env up -d worker`).

## 6. Connecting Notion

Both modes run the same pipeline. **Full OAuth** is the one-time OAuth flow from the project brief; **Quick** skips registering a public app.

### Mode A — Quick (recommended for graders)

Notion calls these **connections** (older docs and screens say "integrations").

1. Open [notion.so/profile/integrations](https://www.notion.so/profile/integrations). Notion shows it as **Developer tools → Developer connections**. Click **+ New connection**:
   - **Name:** anything, for example `AI Note`. **Installable in:** your workspace.
   - **Auth type:** the internal / token option, **not OAuth**.
   - Save. On the connection's page, make sure **Read content**, **Update content** and **Insert content** are on, and copy its secret. It starts with `ntn_`.
2. Create a page titled exactly **AI Video Notes**, and give the connection access to it in either of these ways:
   - Open the page, click the **•••** at the **top-right of the page** (not the right-click menu in the sidebar), choose **Connections** at the bottom (may be labelled **Connect to**), and pick your connection; or
   - On the connection's page, open its **Access** tab, click **Edit access**, and tick the page.

   Check: the page's top-right **•••** → **Connections** now lists your connection. Without this step every job fails with `NOTION_NO_DESTINATION`.
3. Open the extension popup, paste the secret into **Integration token**, and click **Connect with token**.

No `NOTION_CLIENT_*` variables are needed. `NOTION_DEFAULT_PARENT_ID` is optional: when it's empty, the page called "AI Video Notes" is found automatically.

### Mode B — Full OAuth

1. At [notion.so/profile/integrations](https://www.notion.so/profile/integrations) (**Developer connections → + New connection**), create a connection with the **OAuth (public)** auth type:
   - **Redirect URI:** `https://lbmicegifohcileflpbjdanghkgigcia.chromiumapp.org/notion` (the extension ID is pinned, so this is the same on every machine).
   - **Capabilities:** Read content, Update content, Insert content.
   - **Notion URL for optional template:** create a page titled **AI Video Notes**, publish it (**Share → Publish**), and paste its public URL. Notion then copies it into each user's workspace when they connect, and it becomes their default destination.
2. Put the OAuth client ID and secret in `.env` as `NOTION_CLIENT_ID` and `NOTION_CLIENT_SECRET`. Keep `NOTION_REDIRECT_URI` as in `.env.example`.
3. Restart the gateway: `docker compose -f deploy/docker-compose.yml --env-file .env up -d gateway`.
4. The popup now shows **Connect Notion**. Click it once and approve. You won't be asked again until access is revoked.

## 7. API reference

All bodies are JSON. Errors look like `{"error": {"code": "…", "message": "…"}}`.

**Submit a job.** Returns `202` with `{"job_id", "status": "QUEUED", "video_id"}`. `notion_parent_id` is optional ([§4](#4-default-notion-destination)). `Idempotency-Key` is optional: resending the same key returns the same job.
```bash
curl -X POST localhost:8080/jobs -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: 3f1c2a' \
  -d '{"youtube_url": "https://www.youtube.com/watch?v=VIDEO_ID", "notion_token": "ntn_…", "notion_parent_id": "PAGE_OR_DATABASE_ID"}'
```

**Job status.** Returns `status`, `progress` (0–100), `video_title`, `duration_sec`, `warnings`, `waiting` (set while the job waits on a rate limit: `reason`, `provider`, `next_attempt_at`), `error`, `result` and `attempt`.
```bash
curl localhost:8080/jobs/JOB_ID
```

**Results** of a finished job: `{"status", "result": {"notion_page_url", "frames_requested", "frames_published"}, "warnings"}`. Returns `409 JOB_NOT_FINISHED` until the job ends.
```bash
curl localhost:8080/jobs/JOB_ID/results
```

**Health.** Plain `/healthz` checks infrastructure only: Postgres, RabbitMQ, Redis, `workers_alive` and `provider_429_total`. `?deep=1` adds each worker's preflight report: LLM key and model, yt-dlp, ffmpeg, YouTube reachability and the Notion OAuth setup.
```bash
curl localhost:8080/healthz
curl 'localhost:8080/healthz?deep=1'
```

**Notion OAuth config, as used by the extension:** `{"oauth_enabled": true|false, "client_id"}`.
```bash
curl localhost:8080/auth/notion/config
```

**OAuth code exchange.** Full OAuth mode only; the extension calls it after the user approves. Returns the access token and workspace details.
```bash
curl -X POST localhost:8080/auth/notion/exchange -H 'Content-Type: application/json' \
  -d '{"code": "CODE_FROM_NOTION", "redirect_uri": "https://lbmicegifohcileflpbjdanghkgigcia.chromiumapp.org/notion"}'
```

**Destinations** shared with the integration, for the popup's picker: `{"pages": [{"id", "title", "type", "icon"}]}`.
```bash
curl localhost:8080/notion/pages -H "Authorization: Bearer $NOTION_TOKEN"
```

**Admin: dead-lettered jobs**, each with its event history. Replay one: it resumes from its last checkpoint and needs the Notion token again, because tokens are never stored.
```bash
curl 'localhost:8080/admin/dlq?limit=20' -H "Authorization: Bearer $ADMIN_TOKEN"
curl -X POST localhost:8080/admin/dlq/JOB_ID/replay -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' -d '{"notion_token": "ntn_…"}'
```

**Admin: fault injection**, set live without restarting anything. Keys: `llm_429_rate`, `notion_429_rate`, `youtube_429_rate`, `frame_fail_rate` (0–1), `frame_fail_all` (`true`/`false`), `stage_delay_ms`.
```bash
curl localhost:8080/admin/faults -H "Authorization: Bearer $ADMIN_TOKEN"
curl -X PUT localhost:8080/admin/faults -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' -d '{"llm_429_rate": "0.7"}'
```

## 8. Demonstrating failure modes

Start the stack with the demo profile (short retries, slow frames), then run the scripts in `scripts/demo/`. Each ends with a `PASS` or `FAIL` line. [`docs/demo-runbook.md`](docs/demo-runbook.md) gives the presentation order and what to show for each.

```bash
docker compose -f deploy/docker-compose.yml --env-file .env --env-file deploy/demo.env up -d
export NOTION_TEST_TOKEN=ntn_…            # scripts that submit jobs read the token from here
```

Or run a whole round in one go: `scripts/demo/run-all.sh --fresh` (wipes the stack, starts it with the demo profile, runs every script and prints a PASS/FAIL summary).

| Script | Shows | Passes when |
|---|---|---|
| `health.sh` | Sanity check | All checks `ok`, `workers_alive ≥ 2` |
| `happy.sh <url>` | Full flow through the API | Status changes printed; ends `COMPLETED` with a Notion URL and the end-to-end time |
| `burst.sh <url>…` | 6 jobs at once | All complete; `provider_429_total` doesn't change |
| `kill-worker.sh <url>` | SIGKILL the worker holding a job mid-frames | Another worker resumes it within 15 s; exactly one Notion page |
| `force-429.sh llm\|notion\|youtube <url>` | 70 % of calls to one provider return 429 | The job waits instead of failing, then completes |
| `dlq.sh <private-url>` | A video that can never succeed | `DEAD_LETTERED` within 60 s; listed in `/admin/dlq` and the RabbitMQ UI (http://localhost:15672, guest/guest) |
| `frames-fail.sh <url>` | Half the frames fail, then all of them | `COMPLETED_WITH_WARNINGS`, then a text-only page |
| `too-long.sh <url>` | A video over 20 minutes | `FAILED VIDEO_TOO_LONG` before captions are fetched |
| `scale.sh N` | Add or remove workers | `workers_alive = N` |

## 9. Architecture and design choices

```
 ┌──────────────────────── Chrome ─────────────────────────────────┐
 │  Content script ──msg──► Background (service worker) ◄──► Popup │
 │  (Take Notes button)     (OAuth, submit, poll)                  │
 └───────────────────────────────┬─────────────────────────────────┘
                                 │ HTTP JSON
                                 ▼
                        ┌─────────────────┐   OAuth code exchange
                        │   API Gateway   │──────────────────────► Notion OAuth
                        │      (Go)       │
                        └──┬──────────┬───┘
               insert job  │          │ publish (via outbox, confirms)
               + outbox    ▼          ▼
                     ┌──────────┐  ┌──────────────────────────────────┐
                     │ Postgres │  │ RabbitMQ                         │
                     │  (state) │  │  jobs.work ─► jobs.retry.<delay> │
                     └────▲─────┘  │      │          (TTL → back)     │
                          │        │      └─► jobs.dlq                │
            checkpoints,  │        └───────────┬──────────────────────┘
            status, frames│                    │ consume (prefetch 1, manual ack)
                     ┌────┴────────────────────▼────┐      ┌───────┐
                     │  Worker × N (Go)             │◄────►│ Redis │ token buckets,
                     │  Transcribe → Summarize →    │      └───────┘ liveness, faults
                     │  Extract Frames → Publish    │
                     └──┬─────────┬──────────┬──────┘
                        ▼         ▼          ▼
                  YouTube     LLM provider   Notion API
                (yt-dlp,     (Gemini /      (pages, blocks,
                 ffmpeg)      backups)       file uploads)
```

The gateway only accepts and reports jobs; it never runs pipeline work. Each worker runs all four stages and saves a checkpoint after each one, so a retried or redelivered job resumes where it stopped.

| Decision | Choice | Why |
|---|---|---|
| Language | Go | Goroutines and channels for concurrent frames and heartbeats; small static binaries. |
| Broker | RabbitMQ | Native acks and redelivery when a worker dies, dead-letter exchanges, TTL-based delayed retries, delivery limits for poison messages, and a management UI. |
| Job state | Postgres with checkpoints and events | A transaction saves a stage's result and advances the status together; checkpoints make resume possible. |
| Enqueue | Transactional outbox | A job is never lost or duplicated if the broker is down or the gateway crashes right after the commit. |
| Rate limits | Redis token buckets (Lua), shared by every worker, set to ~80 % of the provider's limit | Prevents 429s instead of reacting to them, however many workers run. |
| Retries | One TTL queue per delay plus a dead-letter exchange | Exponential backoff without a scheduler or a sleeping worker. |
| Crash safety | Ack only after the durable commit; leases with Redis heartbeats; idempotent stages | At-least-once delivery is only safe if a redelivery is harmless. |
| Frames | ffmpeg seeks on the stream URL, snaps to slide changes and keeps the sharpest of 3 candidates | Every image is a real frame at the right moment, without downloading the whole video. |
| LLM | Gemini Flash free tier behind a provider interface, with Groq/OpenRouter backups | Free and image-capable; the tight free limits show the rate limiter working. |
| Notion token | Passed per job, AES-GCM encrypted in the broker, never stored | The gateway never keeps the token, and queued messages are safe at rest. |

## 10. Troubleshooting

**"Sign in to confirm you're not a bot" (doctor or job logs).** YouTube is blocking requests from your network.
1. Install a cookies.txt exporter in Chrome (for example "Get cookies.txt LOCALLY"), open youtube.com while signed in, and export `cookies.txt`.
2. Save it as `.ytdlp/cookies.txt` in the repo (the folder is git-ignored and mounted into the workers).
3. Add `YTDLP_COOKIES_FILE=/ytdlp/cookies.txt` to `.env`, then restart the workers: `docker compose -f deploy/docker-compose.yml --env-file .env up -d worker`.

**Jobs keep waiting on `llm`, or the quota runs out.** The free tier allows few requests per day. The job waits and resumes when tokens come back; it doesn't fail. To keep going, add a backup (`LLM_FALLBACK_PROVIDER=groq` with `GROQ_API_KEY`), or switch `LLM_PROVIDER`. If `scripts/doctor.sh` reports "LLM key rejected", the key or `LLM_MODEL` itself is wrong.

**Notion OAuth fails with a redirect mismatch.** The public integration's redirect URI must be exactly `https://lbmicegifohcileflpbjdanghkgigcia.chromiumapp.org/notion` and match `NOTION_REDIRECT_URI`. Restart the gateway after changing `.env`.

**`NOTION_NO_DESTINATION` or `NOTION_PARENT_NOT_FOUND`.** The page isn't shared with the connection. Open the page → **•••** (top-right of the page) → **Connections** → add the integration.

**The extension can't reach the gateway.** Check `curl localhost:8080/healthz`. If you changed the extension's gateway URL in the popup's settings, it must match. `CORS_ALLOWED_ORIGINS` must contain `chrome-extension://lbmicegifohcileflpbjdanghkgigcia`.

**Port already in use (8080, 5672 or 15672).** Stop the other program, or change the host side of the port mapping in `deploy/docker-compose.yml` (for example `"8081:8080"`) and point the extension at the new URL.

**Start completely fresh.** `docker compose -f deploy/docker-compose.yml down -v` removes all jobs and queues.
